# 手机端接入：iOS 快捷指令 A（上传）+ B（取回）

> **适用版本：iOS 17 / iOS 18**（按这两代系统的“快捷指令”界面写，不是最新版的界面）。
> 用法是 **在语音备忘录里点分享 → 选这两个快捷指令**，不依赖“获取最近语音备忘录”这类动作
> （iOS 17 上没有能直接读语音备忘录列表的动作，所以分享表单是主路径）。

目标流程：语音备忘录里选中一段录音 → 分享 → **快捷指令 A** 上传到电脑转写（立刻告诉你大约等多久）→
等够了点 **快捷指令 B** → 文本自动进备忘录，可以随时连着传多条。

---

## 0. 电脑侧先做好三件事

1. **启动服务**（保持窗口开着）：

   ```bat
   cd project4-vosk-cn\server
   start_server.bat
   ```

   看到 `接口启动 v1.0，监听 0.0.0.0:8765` 即可；worker 会自动拉起，模型加载约 12 秒。

2. **放行防火墙（只需做一次，必须管理员）**：
   右键 `server\allow_firewall.bat` → **以管理员身份运行**。
   这一步会删掉系统里针对这个 Python 的“入站阻止”规则，并放行 TCP 8765。

3. **手机和电脑都登录 xEdge**（同一个微信/GitHub 账号），手机打开 xEdge 的组网开关，
   然后在手机浏览器打开：

   ```
   http://100.64.0.1:8765/api/health
   ```

   能看到 `{"status":"ok", ...}` 就通了。

   `100.64.0.1` 是 **xEdge 给这台电脑的固定私网地址**，在家里 Wi-Fi 下、在外面用 4G/5G 流量下**都是这一个地址**，
   不会像路由器分配的内网 IP（192.168.x.x）那样换网络就变。所以下面两个快捷指令里写死 `100.64.0.1` 就行。

> 家里 Wi-Fi 下也可以继续用 `http://192.168.1.10:8765`，但它只能在局域网内用；手机在外一律用 `100.64.0.1`。

**关于流量**：xEdge 同一局域网/能打洞时是点对点直连、不限速也不走它的中继；
免费版中继额度 1GB/月，超了会降到 1Mbps。

不过要注意，**真正的大头是音频本身的体积**：语音备忘录的 m4a 大约 **30~35MB / 10 分钟**（40 分钟约 100MB）。
所以：

- **在家**：走局域网地址（见下面 0.1），完全不过 xEdge，也不耗手机流量；
- **在外面用流量**：先在快捷指令里压缩音频（见 0.2），10 分钟录音能从 32MB 压到 3~4MB，省 90%。

## 0.1 选对地址：在家走局域网、在外面走 xEdge

两个地址都是同一台电脑同一个服务：

| 场景 | 地址 | 特点 |
|---|---|---|
| 手机连着家里的 Wi-Fi | `http://192.168.1.10:8765` | 局域网直连，最快，不经过 xEdge，不占中继额度 |
| 手机在外面（4G/5G 或其他 Wi-Fi） | `http://100.64.0.1:8765` | xEdge 私网地址，能打洞就直连，打不通才走中继 |

`/api/health` 的返回里直接给出了这两个地址（`addresses.lan` / `addresses.xedge`），
电脑上改完网络可以打开确认一下（可能不是 `192.168.1.10`，以这个字段为准）。

### 做法一（推荐）：另存一套“家里版”快捷指令

不用改原来的，直接复制一套，只把地址换成局域网 IP：

1. 快捷指令 App 里**长按**「录音转文字-上传」→ 点 **复制**，得到「录音转文字-上传 1」；
2. 打开副本，把上传 URL 里的 `http://100.64.0.1:8765` 改成 `http://192.168.1.10:8765`；
3. 改名为 **「🏠 录音转文字-上传」**（前面加个 🏠，分享面板里一眼能分出来）；
4. 同样复制一份「录音转文字-取回」，URL 改成
   `http://192.168.1.10:8765/api/next/text?title=1`，改名 **「🏠 录音转文字-取回」**。

用法：

| 场景 | 用哪个上传 | 用哪个取回 |
|---|---|---|
| 在家连着 Wi-Fi | 🏠 录音转文字-上传 | 🏠 录音转文字-取回（或普通版都行） |
| 在外面 | 录音转文字-上传 | 录音转文字-取回 |

> 家里那条只在内网有效，所以建议**只放在分享表单里**（ⓘ 里勾“在共享表单中显示”），
> 出门时手滑点了会提示“无法连接服务器”，改点另一个就行。
> 取回动作下载的只是文本（几 KB），在家用哪条都无所谓。

**局域网地址会变怎么办**：路由器一般会把同一台电脑分到同一个 IP，但重连/重启后可能变成
`192.168.2.x` 别的值。到时打开 `http://100.64.0.1:8765/api/health`，看 `addresses.lan` 字段
就是当前局域网地址，把快捷指令里那段改掉即可。想彻底固定，可以在路由器里给电脑做“IP 与 MAC 绑定”。

### 做法二：一份快捷指令里自动判断 Wi-Fi

如果不想维护两套，也可以在**两个快捷指令的最前面**都插一段“判断当前 Wi-Fi”，
得到一个变量 `BASE`，后面的 URL 用 `BASE/api/...`：

| # | 动作 | 设置 |
|---|---|---|
| 1 | **获取网络详细信息** | （什么都不用填，拿到当前网络的信息） |
| 2 | **获取字典值** | 第 1 步结果的键：**网络名称** |
| 3 | **如果** | 第 2 步的结果 **包含** 你家 Wi-Fi 的名字（比如 `MyHomeWiFi`） |
| 4 | ↳ **文本** | `http://192.168.1.10:8765` |
| 5 | **否则** | |
| 6 | ↳ **文本** | `http://100.64.0.1:8765` |
| 7 | **结束如果** | |
| 8 | **设定变量** | 变量名 `BASE`，值为第 4/6 步那个「文本」的结果 |

然后 A 的上传 URL 写成 `BASE` + `/api/upload`（在 URL 输入框里先插入变量 `BASE`，再接着打 `/api/upload`），
B 的 URL 写成 `BASE` + `/api/next/text?title=1`。

> 两个做法都嫌麻烦时，也可以一直用 `100.64.0.1` —— 在家里 xEdge 一般也能打洞直连
> （实测 `via 192.168.2.101`，6ms），只是多绕一层虚拟网卡、且万一打洞失败会消耗中继额度。

## 0.2 用流量时先把音频压小（能省 90%）

语音备忘录分享出来的 m4a 码率不低（10 分钟约 32MB），手机流量上传大头都在这。

在快捷指令 A 的「获取 URL 内容」**前面**插一个 **编码媒体**：

| 动作 | 设置 |
|---|---|
| **编码媒体** | 音频：**AAC**；质量：**低**（或“中”）；声道：**单声道**；输入选 `快捷指令输入` |

转出来的 m4a 约 **32kbps 单声道**（10 分钟 ≈ 2.4MB）。Paraformer 识别 16k 单声道足够，
实测压缩后识别效果没有可见下降（服务端本来也会统一重采样到 16kHz 单声道）。

> 压缩后用「文件详情 / 名称」拿到的文件名可能变成 `编码后的音频.m4a`，不影响转写，
> 只是备忘录标题会按这个名字生成。

## 1. 接口一览（电脑上也能用 curl 测）

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/upload` | POST | 上传音频（multipart，字段名 `file`），返回 `task_id`、`eta_seconds`、`queue_position` |
| `/api/upload/raw` | POST | 上传音频的**备选**：请求体直接就是文件（iOS 17 表单上传不好使时用），文件名放 `X-Filename` 头或 `filename` 参数 |
| `/api/next/text` | GET | **快捷指令 B 用**：返回下一条“已完成且没取走”的文本；没有就绪的**立刻回 204 空响应（什么内容都没有）**（不会等，也不会给正在转写的半成品）。`&title=1` 插一行标题，`&wait=N` 才短暂轮询（默认 0），`&blank=200` 把“空”退化成 200 空正文。`&task_id=xxx` 点名取某一条（不排队、取过也能再取） |
| `/api/next` | GET | 同上但返回 JSON（含文件名、时长），`peek=1` 只看不取；队列在忙时返回 **202** |
| `/api/task/{id}` | GET | 查单条状态 |
| `/api/task/{id}/text?title=1` | GET | **取指定任务的文本**（随便取多少次，不影响取件队列；手机上直接用 Safari 打开就能看/复制） |
| `/api/task/{id}/requeue` | POST | 把已完成的转写**重新放到取件队首**（不重转），方便再点一次 B 导进备忘录 |
| `/api/tasks?undelivered=1` | GET | 最近任务列表（`undelivered=1` 只看还没取走的），调试/排查用 |
| `/api/backup` | POST | 立刻给数据库做一次快照（服务每天也会自动做） |
| `/` | GET | 网页版任务列表（显示“待取件”条数，每行有「文本」链接），5 秒自动刷新 |

`/api/next/text` 的返回约定：

- **200 + 转写文本**：正文就是转写文本，响应头 `X-Task-Id` / `X-Filename`（文件名 URL 编码）；
- **204 No Content（没有任何正文）**：**当前没有就绪的文本**——包括两种情况：①一条都还没传；
  ②刚传的还在排队/转写中。响应头 `X-Pending` 会带上还有几条在转，方便排查；
- 快捷指令里判断第 1 步的“内容”**没有值**（`是` 空 在 iOS 17 上不稳，别用）：
  没有文本 → 弹“还没转好” → 停止；有文本 → 新建备忘录。
- 如果某个 iOS 版本把 204 当成错误（弹“无法完成”），在 URL 末尾加 `&blank=200`，
  服务端就改成“200 + 空正文”，行为一样是“什么内容都没有”。
- 响应带 `Cache-Control: no-store`，避免任何一端的缓存把旧文本留住。

取件的范围**只有**“转写完成、还没被取走”的任务：正在转写的任务、临时文件、上传中的文件都不会出现在 B 里。

取过一次就标记 `delivered=1`，下一条不会重复。

**但文本本身永远不会丢**：被取走只是“出队”，任何一条都能随时按任务号再拿一次：

- 手机 Safari 直接打开 `http://100.64.0.1:8765/api/task/<任务号>/text`（加 `?title=1` 带标题行）；
- 或者 `POST http://100.64.0.1:8765/api/task/<任务号>/requeue`，再点一次 B 导进备忘录；
- 或者 `GET .../api/next/text?task_id=<任务号>`，直接取回那一条。
- 电脑上：`server\data\records\` 里每次转写都有一个 txt，`data\backup\` 有数据库快照。

**重复上传同一段音频不会重复消耗算力**：服务端会对上传的文件算 SHA-256，
如果这段音频之前传过（还在队列里、正在转、或者已经转完），直接返回那条旧任务：

```json
{"task_id":"281fd42fa71d","status":"done","duplicate":true,
 "eta_seconds":0,"text":"……（全文）","text_len":13005,"deliverable":true,
 "message":"这条音频之前已经转写过，已重新放回取件队列，点「取回」即可拿到文本"}
```

已转完的旧任务会被**重新放回取件队首**（下一条取件就轮到它），而且 `text` 字段里就是全文，
快捷指令 A 想直接导出也行（取 `text` 字段即可）。确实要强制重转（比如改了 `corrections.txt`），
上传 URL 后面加 `&force=1`。

## 2. 快捷指令 A：上传（从语音备忘录分享进来）

新建快捷指令，命名 **“录音转文字-上传”**。

### 2.1 先打开分享入口（关键）

点右上角 **ⓘ**（iOS 18 在右上角「…」里的“详细信息”）：

| 设置项 | iOS 17 / 18 上怎么填 |
|---|---|
| **在共享表单中显示** | 打开（iOS 18 叫“在共享表单中显示”，开关样式不同，效果一样） |
| **接收来自共享表单的输入 / 接受类型** | 勾上 **媒体** 和 **文件**（语音备忘录分享出来的是 m4a 音频文件，两种类型都能匹配） |

打开后，语音备忘录里点「…」→ 分享 → 往下翻，就能看到这个快捷指令。

### 2.2 动作

| # | 动作 | 设置 |
|---|---|---|
| 1 | **如果** | 条件：**快捷指令输入** “没有值”（防止直接点图标运行时崩掉） |
| 2 | ↳ **显示提醒** | “请从语音备忘录里分享后运行” |
| 3 | ↳ **停止此快捷指令** | |
| 4 | **结束如果** | |
| 5 | **获取 URL 内容** | URL：`http://100.64.0.1:8765/api/upload`<br>方法：**POST**<br>请求体：**表单**<br>新字段：键 `file`，类型 **文件**，值选 `快捷指令输入`<br>（可选）再加字段 `client`，类型 文本，值 `iphone` |
| 6 | **获取字典值** | 获取 **第 5 步的结果** 里的 `eta_seconds` |
| 7 | **显示结果** | “已上传，预计 **`第 6 步的字典值`** 秒后可以取文本” |

说明：

- 第 5 步的“类型：文件”是在表单字段的 **类型** 下拉里选，iOS 17 和 18 都有；选错成“文本”会得到 422；
- 分享进来的东西在快捷指令里统一叫 **快捷指令输入**（变量），不用自己再“获取文件”；
- A 只负责上传，不写备忘录、不判断重复——重复的音频服务端会直接复用旧结果（等待 0 秒），
  取回时旧记录会被放到取件队首，点 B 就能拿到；
- **用流量时**，先在前面插一个 **编码媒体**（AAC / 单声道），文件缩到 1/10 再传，详见 0.2；
- 单文件上限是 `config.py` 的 `MAX_UPLOAD_MB=1024`（1GB）——一小时以上的语音备忘录常见 200~400MB，够用；
  万一超了，服务端回 **413**，A 拿不到 `eta_seconds` 所以什么都不显示，这时先压缩或者把这个上限调大。

### 2.3 先验证“上传能成”

语音备忘录里分享一段 10 秒的录音给这个快捷指令，应该弹“已上传，预计 3 秒后可以取文本”。
如果报 **422 / 空文件 / 上传没反应**，说明 iOS 17 的“表单 + 文件”没把文件带上，直接改走 2.4 的备选方案。

### 2.4 备选：raw 上传（表单不好使时用这个）

电脑端已经加了这个接口：请求体**直接就是音频文件**，文件名走请求头。

| # | 动作 | 设置 |
|---|---|---|
| 1 | **获取文件详情** | 文件：`快捷指令输入`；属性：**名称** |
| 2 | **URL 编码** | 输入：第 1 步的名称（得到 `%E5%BD%95%E9%9F%B3...`） |
| 3 | **获取 URL 内容** | URL：`http://100.64.0.1:8765/api/upload/raw`<br>方法：**POST**<br>请求头：键 `X-Filename`，值 **第 2 步的编码结果**<br>请求体：**文件**，值选 `快捷指令输入` |
| 4 | **获取字典值** | 第 3 步结果的 `eta_seconds` |
| 5 | **显示结果** | “已上传，预计 X 秒后可以取文本” |

（如果 `X-Filename` 头被吃掉，也可以把文件名拼进 URL：`.../api/upload/raw?filename=第2步的编码结果`，两者都支持。）

### 2.5 想从“文件”App 选 m4a 也行

如果录音是通过微信/AirDrop 存成文件而不是在语音备忘录里，把第 5 步（或 2.4 第 3 步）的文件值换成 **选择文件** 动作即可。

## 3. 快捷指令 B：取回文本写进备忘录

新建 **“录音转文字-取回”**（不需要分享表单，直接点图标运行即可）。

| # | 动作 | 设置 |
|---|---|---|
| 1 | **获取 URL 内容** | URL：`http://100.64.0.1:8765/api/next/text?title=1`<br>方法：GET |
| 2 | **如果** | 条件：第 1 步的“内容”**有值**（没有就绪文本时服务端回 204、什么内容都没有） |
| 3 | ↳ **新建备忘录** | 内容：第 1 步的“内容”（写进“备忘录”App，默认文件夹） |
| 4 | **结束如果** | |
| 5 | **获取 URL 内容** | URL：`http://100.64.0.1:8765/api/recent`<br>方法：GET（拿到“最近转写记录”清单，**默认全部**） |
| 6 | **显示结果** | 内容：第 5 步的“内容”（弹出清单，每行是一个编号 + 标题） |
| 7 | **要求输入** | 类型：**文本**；提示：“要重建哪条的备忘录？输入上面的编号（直接取消就退出）” |
| 8 | **如果** | 条件：第 7 步的“提供输入”**有值** |
| 9 | ↳ **获取 URL 内容** | URL：`http://100.64.0.1:8765/api/recent/text?title=1&pick=`**`第 7 步的提供输入`**<br>方法：GET |
| 10 | ↳ **新建备忘录** | 内容：第 9 步的“内容” |
| 11 | ↳ **显示通知** | “已按编号重建备忘录” |
| 12 | **结束如果** | |

要点：**B 只取“已经转好”的文本**，没转好时服务端立刻回 204（什么内容都没有），第 2 步判“有值”就不会写空备忘录。
所以 A 显示“预计 N 秒后可以取文本”之后，等够了再点 B 就行；早了就只会在清单里看到以前转过的记录。

**第 5 步以后是“重建历史备忘录”**：不管这次有没有取到新文本，都会把**全部**转写记录列出来（最新在前），
长这样：

```
1. 导论-竞赛 · 40 分 22 秒 · 11-02 16:57
2. 导论 · 43 分 53 秒 · 11-02 16:57
3. 心理课 · 41 分 45 秒 · 11-02 16:56
4. 学姐分享 · 6 分 24 秒 · 11-02 16:56
5. 开会-天竹 · 16 分 50 秒 · 11-02 16:56
...
30. 会议录音 · 4 分 46 秒 · 10-29 16:47

输入编号重建备忘录：1~30（对应上面的编号）
```

输入 `3` 就会把「心理课」重新写成一条新备忘录（带标题行）；想输任务号也行
（`9615f0cf654f`，从 `/` 网页或 `/api/tasks` 里抄）。
直接点“取消”就不重建，刚才取到的新文本已经在备忘录里了。

> 记录多了以后清单会很长——嫌麻烦就在 URL 后加 `?limit=20` 只看最近 20 条（`0` = 全部，默认）。
> 之前我测试用的几十条 `sample_zh`、`deo_16k` 等已经标成 `hidden`，不会出现在清单里
> （文本和 txt 存档都还在，`tests\hide_test_tasks.py --unhide` 可以放回来）。

> 不想每次弹清单？把第 5–12 步删掉，就退回“只取新文本”的老版本。
> 清单条数改 `limit=` 即可（`0` = 全部，默认；`20` = 最近 20 条，最大 500）。

> **判断一定要用「没有值」**：iOS 17 里 204 / 空正文会被「获取 URL 内容」当成“没有值”，
> 而「如果 内容 是 空」这种写法判不出来，流程就会继续走到「新建备忘录」，
> 备忘录没内容于是弹“备忘录如何命名”。用「内容 没有值」就正好对上。
>
> 如果你的 iOS 版本对 204 直接报错（弹“无法完成”），就把 URL 改成
> `.../api/next/text?title=1&blank=200`，服务端改成 200 空正文，判断仍然用「没有值」。

> 如果 URL 里还留着 `&wait=120`（老版本这样写），请求会最多占用 2 分钟才返回空 ——
> 新版建议**去掉 wait**，改成 `?title=1`，点一下立刻有结果。

**循环版**（长录音或一次传了好几条，想一直等到取到为止）：

| # | 动作 | 设置 |
|---|---|---|
| 1 | **重复** | 30 次 |
| 2 | ↳ **获取 URL 内容** | `/api/next/text?title=1` |
| 3 | ↳ **如果** | 内容 **有值** |
| 4 | ↳↳ **新建备忘录** | 内容 |
| 5 | ↳↳ **停止此快捷指令** | |
| 6 | ↳ **结束如果** | |
| 7 | ↳ **等待** | 5 秒 |
| 8 | **结束重复** | |

> 这样每 5 秒问一次，直到某条转好为止，最长等 2.5 分钟。

> iOS 18 的“如果”可以一行写“与”条件；iOS 17 里如果找不到组合条件，就嵌套两层“如果”。

**iOS 17 与 iOS 18 的差别**（只影响操作方式，不影响这两个快捷指令的接口）：

- iOS 18 在「新建备忘录」上多了“使用默认文件夹”等选项，iOS 17 直接写默认文件夹；
- iOS 18 的“如果”条件可以一次加多个，iOS 17 需要嵌套；
- 两代都能用「显示通知」「显示提醒」「重复」「停止此快捷指令」这些动作，名字一致。

### 3.1 文字进备忘录后变成大号标题字？

备忘录（Notes）会把正文的**第一行**自动当作标题，用大号字显示。转写结果一般是一整行长文本、中间没有换行，
于是整段都被当成“标题”，看起来就是满屏大字。

三种解法，任选一种：

1. **让服务端插一行标题（推荐，已内置）**：B 的第 1 步 URL 末尾加 `&title=1`：
   `http://100.64.0.1:8765/api/next/text?title=1`
   返回内容会变成：

   ```
   新录音 3 · 1 分 12 秒 · 10-30 15:39

   今天天气不错，我们一起去公园散步吧。……
   ```

   第一行是小标题（日期/时长/文件名），正文恢复成正常小字。标题格式为
   `<文件名> · <时长> · <月-日 时:分>`，同时通过响应头 `X-Title`（URL 编码）返回。

2. **在快捷指令里自己拼**：B 的第 1 步后面加一个「文本」动作，内容写成两行——标题、空行、正文
   （正文引用第 1 步的“内容”），再把这个「文本」喂给「新建备忘录」。

3. **改用「追加到备忘录」**：追加到你自己建好的那条笔记（比如标题叫“语音转写”），
   每次转写的结果都会以正文小字接在末尾，标题一直是那一条。适合长期攒录音笔记。

## 4. 在电脑上验证（可选，但建议先跑一遍）

```bat
:: 上传（表单，同快捷指令 A 的主路径）
curl -X POST http://127.0.0.1:8765/api/upload -F "file=@..\audio\sample_zh.wav"
```

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 分享面板里找不到这个快捷指令 | 快捷指令 ⓘ 里没打开“在共享表单中显示”，或接受类型没勾“媒体/文件” |
| 跑 A 报 **422** / 服务器日志里“空文件” | iOS 17 表单+文件没带上文件 → 改用 2.4 的 `/api/upload/raw` 写法 |
| 跑 A 弹“请从语音备忘录里分享后运行” | 直接点了图标，没有传输入；从语音备忘录分享进来即可 |
| 手机打不开 `api/health` | xEdge 没连（控制中心看 VPN 图标）；防火墙没放行（管理员跑 `allow_firewall.bat`）；或电脑服务没开 |
| 家里 Wi-Fi 能开、出门打不开 | xEdge 手机端没登录/没开组网开关；iPhone「设置 → VPN」里 xEdge 配置未连接 |
| 上传成功但一直取不到 | 看 `/`（网页任务列表）或 `/api/health` 里的 `worker.alive`；worker 挂了会 5 秒内自动重启 |
| 刚上传完点 B 就提示“还没有转好的文本” | 正常。B 只取已经转完的；等 A 显示的预计时间到了再点一次（长录音要等更久） |
| 一小时以上的录音，A 什么都没弹、记录里也没有 | 文件超了上限被 **413** 拒了（旧版上限 200MB，现在 1024MB）。`server\data\logs\server.log` 里能看到 `→ POST /api/upload len=…` 紧接 `← … 413`；先「编码媒体」压缩，或调大 `config.py` 的 `MAX_UPLOAD_MB` 后重启 |
| 点 B 卡住几十秒才有反应 | URL 里还留着 `&wait=120`（老写法），去掉它、只留 `?title=1` 就是立刻返回 |
| 返回什么都没有（204） | 当前没有“已完成且没取走”的文本：要么还没传，要么还在转；`/` 页面能看到队列 |
| 队列一直不动 | 看 `/api/health` 的 `worker.alive`；worker 挂了会 5 秒内自动重启 |
| 文本有错别字 | 改 `corrections.txt`（`错词 => 正确词`），下次转写自动生效 |
| 同一段录音传了两次 | 第二次直接返回旧任务（`duplicate: true`、等待 0 秒）**并把它放回取件队首**，`text` 字段里就是全文；要强制重转在 URL 后加 `&force=1` |
| 大文件在转、又传了小文件，取回来的顺序是什么 | 按**转写完成时间**排：先转完的先给你。刚上传完还没转完时点 B 是 204，等它转完再点就是它的文本 |
| 取走之后发现备忘录没建好，想再取一次 | 文本不会丢：点一次 B，在弹出/输入的清单里输入对应**编号**（1 = 最新），就会重新建一条；也可以 Safari 打开 `http://100.64.0.1:8765/api/task/<任务号>/text` 直接看 |
| 清单里的编号怎么用 | 打开 `http://100.64.0.1:8765/api/recent` 就能看到同样一份清单；记住某条编号后，打开 `http://100.64.0.1:8765/api/recent/text?pick=编号&title=1` 就是那条的全文 |
| 不知道某条录音的任务号 | 打开 `/`（网页任务列表）或 `http://100.64.0.1:8765/api/tasks?limit=20`，每行/每条都有 `id` 和「文本」链接；也可以直接开 `http://100.64.0.1:8765/api/task/<任务号>/text`，或 `POST .../api/task/<任务号>/requeue` 后点一次 B |
| 想翻以前的转写 | `server\data\records\` 里每份都是 txt（带头部信息），`index.jsonl` 是索引；数据库快照在 `server\data\backup\`（保留 14 份） |
| 在家里也怕耗流量 | 用「🏠 录音转文字-上传」（局域网地址 `192.168.1.10`），详见 0.1 |
| 电脑重启后忘了开服务 | 把 `start_server.bat` 的快捷方式丢进 `shell:startup`；xEdge 服务本身是自启的 |
